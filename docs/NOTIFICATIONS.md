# 库存通知与北京时间免打扰

系统的“通知设置”页面提供两种 Telegram 通知模式。

- 仅补货推送（默认）：补货时发送新卡片；已有卡片的库存变化、售罄在原卡片编辑。
- 全部库存变化推送：监控范围内的补货、库存数量变化和售罄，各发送一条新的卡片消息。即使该套餐以前没有发送过补货卡片，也能推送数量变化与售罄。公开数量与未公开数量之间的变化也会通知。状态不变时不重复发送。

切换模式不会批量推送已有套餐。GreenCloud 首次成功抓取继续只建立库存基线；后续变化通知。新增监控和勾选套餐遵循现有范围设置；删除、停用监控或取消套餐选择后，不会继续发送该范围的通知。全部变化模式的历史卡片保留检测当时的状态，不原地覆盖；卡片上注明检测时间（北京时间）。

免打扰固定为北京时间（Asia/Shanghai，UTC+8），独立于 VPS 和浏览器的本地时区。开始时间包含，结束时间不包含；支持跨午夜，例如 23:00–08:00。开始与结束不能相同。默认关闭；开启时必须设置有效的 HH:mm 区间。

免打扰期间继续抓取并记录变化，通知保存在 SQLite 中，重启不会丢失。期间 Telegram 发送、编辑和手动连通性测试都暂停。全部变化模式在区间结束后补发各次变化的历史快照；卡片的检测时间可以区分历史消息。默认模式仍会取消已经过期的补货消息，保留原卡片编辑逻辑。切回默认模式时取消尚未发送的全部变化库存与售罄新消息。

API：`PUT /api/settings` 的 `telegram` 区块支持 `notificationMode: "restock" | "all"` 和 `quietHours: { enabled: boolean, start: "HH:mm", end: "HH:mm" }`。不接受自定义时区。Bot Token 留空时保留原密钥。

Telegram 的实际网络调用统一检查免打扰，后台队列与手动测试共用该规则。通知及连通性测试遵守免打扰；私聊管理菜单的读取、操作反馈和按钮响应不受免打扰限制。

## 私聊管理菜单

后台配置的个人 User ID 是唯一管理员，仅允许该用户在私聊发送管理命令，无需绑定。
`/menu` 打开管理菜单；`/status`、`/monitors`、`/stock`、`/notifications`、`/events`、`/help` 可直接进入相应页面。
按钮导航更新原消息，套餐按页编号并对应购买按钮，时间统一为北京时间。

监控详情 → 检查间隔 → 自定义，输入 `75`、`75秒`、`5m` 或 `5分钟`，支持 30–3600 秒整数。
输入五分钟内有效，`/cancel` 或点击其他菜单按钮取消；非法输入不改变原设置。
删除及批量暂停使用两分钟内有效的一次性确认按钮。通知目标开关与管理员权限相互独立。
Bot 通过 Worker 长轮询接收消息，保存处理进度；已有 Webhook 时报告冲突，不自动删除。

## 新套餐上架

独立开关 `telegram.notifyNewPlans` 默认开启。首次采集建立商家基线；后续新套餐（包括新分类和已售罄套餐）按稳定套餐 ID 去重，配置自动解析，发送“新套餐上架”卡片。选定套餐或分类范围只限制常规库存通知；新套餐通知覆盖商家全部新增套餐，以便发现黑五、圣诞等限时新产品。商家监控须启用。

开启后不补发历史已有套餐。关闭开关取消尚未投递的新套餐任务；TG 总开关、监控暂停和免打扰保留待发送任务，恢复后投递检测时快照。切换库存通知模式不丢失新套餐任务。新套餐卡片保留配置、价格、库存状态、购买链接和检测时间。
