# 修复与回归报告

日期：2026-10-07。对应 [原测试报告](TEST-REPORT.md) 中实际复现的 18 个问题。

## 修复内容

- 监控编辑先解除 Vue Proxy 再复制；浏览器验证编辑、保存间隔和重新打开。
- 通知由 Worker 统一发送，API 手动运行只入队。SQLite 原子领取任务，60 秒租约允许异常退出后恢复，15 秒请求超时避免正常请求超过租约；旧持有者不能确认新租约任务。
- 队列关联监控任务、补货周期和售罄消息快照。取消过期补货，保留旧周期售罄消息的 messageId；发送期间库存变动不会覆盖新状态，并补入必要的编辑任务。
- 关闭 TG / 暂停任务时暂停投递；删除任务事务清理队列。探测期间删除任务不会将任务重新写回。
- TG 相同内容编辑视为成功；400 / 401 / 403 / 404 永久错误记录原因并停止重试；429 / 临时错误仍重试。标签转义 HTML，购买链接限制 http / https。
- Worker timer 提前声明，启动前已有重启标记能正常退出，重复关闭请求不会重复关闭数据库。
- 设置接口采用字段白名单和类型校验，禁止客户端覆盖密文；JSON 解析错误返回 400；缺失远端分支拒绝部署。Git 检查设置 20 秒超时。
- 明文 Token 迁移为加密设置，并脱敏本次生成的归档；缺少密钥时回滚并保留源文件，允许配置后重试。初始化失败关闭数据库连接。
- 心跳按 30 秒窗口判断在线，10 秒刷新状态；后台刷新不覆盖未保存的设置。事件页独立获取完整事件列表。
- 设置保存成功后清空 Token 并重新生成预览；移动端导航可收缩，长文本换行。

## 范围与限制

所有测试使用隔离数据库和虚构数据，没有访问真实商家套餐或发送真实 TG 消息，没有执行真实在线更新、Docker 部署或 systemd 安装。原报告中备份恢复、队列管理页面、更新回滚等新增功能建议不属于本轮缺陷修复。

数据库通过新增 notification_claims 表兼容现有数据；已有队列通过商家关联推断任务。旧任务没有补货周期或快照，无法完整还原此前发生的多个周期，新产生的任务包含完整关联信息。

租约解决多个进程同时领取同一任务。若 Telegram 已接收消息但进程在保存 messageId 前崩溃，仍存在再次发送的可能；Telegram sendMessage 没有本实现可用的服务端幂等键。已发出的网络请求无法在之后关闭通知时撤回。

本文件记录修复完成时的验收结果；后续版本发布说明见 RELEASE-v1.3.0.md。
