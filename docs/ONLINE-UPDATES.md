# 在线更新

访问 `/admin#settings`，点击“检查更新”。检查过程中按钮显示“正在检查…”，新版本可安装时自动弹出站内确认框；“暂不更新”不执行写入，“确定更新”才启动更新。下载包缺失或网络异常的原因显示在版本状态区域。

安装包部署从所配置 GitHub 仓库的最新正式 Release 读取 `vps-monitor-x.y.z-linux-x64.tar.gz` 和 `SHA256SUMS`。平台必须为 Linux x64。版本比较使用数字，而非字符串比较；只安装更高版本。下载地址须属于对应仓库和版本；下载大小有上限，校验 SHA256、清单版本、平台与依赖清单，并拒绝越界压缩包路径和链接。

确认后的顺序：下载发布包、校验与解压、暂停 Worker 并等待当前任务结束、备份现有部署、替换应用文件、自动重启 API 和 Worker、浏览器恢复连接并刷新。保留数据库、`.env`、systemd 环境配置、登录和 TG 设置。重启的是项目服务，不重启整台 VPS；使用已有 systemd `Restart=always` 自动拉起服务。

源码部署继续要求工作目录干净、origin 与设置匹配，并使用快进合并；依赖安装和前端构建在进度中显示，失败回退原修订和备份文件。生产安装包部署不需要 Git 或在线 npm install。

`GET /api/updates/status` 检查远端版本；`POST /api/updates/apply` 确认并启动，返回 202；`GET /api/updates/progress` 返回阶段、百分比、消息和目标版本。接口均需登录。前端提交确认时看到的目标版本或 Git 修订，远端已变化则要求重新检查。重复任务返回 409。

更新状态写入数据目录 `.update-status.json`，备份位于 `update-backups/`。下载或校验失败不会修改部署，文件替换失败恢复已替换目录；失败弹窗支持重新检查。服务重启短暂断连时自动重试；重启后验证目标版本并标记完成。页面手动刷新可恢复正在进行的进度弹窗。当前更新成功完成的状态在数据目录保留供排障查看。
