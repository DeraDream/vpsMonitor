# GreenCloud（1.4.0）

商家模块独立位于 `packages/adapters/src/greencloud/`，包括 `index.mjs`、`parser.mjs` 和去除会话信息的测试 fixtures。Bero 仍位于独立的 `bero-host` 文件夹，两者只共享注册入口和公共模型。

从 `https://greencloudvps.com/billing/store` 的分类导航动态发现公开分类；套餐数量、名称、配置、价格和订购地址均来自当前页面，不硬编码分类列表或套餐数量。已有但移出目录的分类保留历史元数据，其套餐不列为当前套餐；目录重新出现后正常抓取恢复。某类请求失败仅保留该类旧状态，并标记错误；目录本身失败则为已知分类记录失败，防止旧通知在未知状态下投递。

库存依据明确数量优先：`0 Available` 为缺货，正数为有货。无数量且提供有效公开 Order Now 链接的套餐标为“可订购 · 数量未公开”，`quantity=null`，不宣称数量无限。此类与明确有货分别统计，TG 使用“可订购提醒”。明确售罄或禁用按钮为不可售。订购页面可能有额外限制，最终购买资格以商家结账页面为准。抓取只请求目录和分类的公开 GET 页面，不访问加入购物车链接，不登录，不下单。

配置解析支持结构化 feature-value 列表及描述型套餐。公共模型新增 `storage`、`storageType`、`bandwidth`、`portSpeed`、`os`、`controlPanel`、`virtualization`、`description`、`availabilitySource`；既有 CPU、RAM、NVMe、IPv4/IPv6、备份、周期仍保留。完整原字段保存为 configuration，保留混合磁盘及合并 IP 的原描述，不把 SATA 或 SSD 伪装成 NVMe。Starting from 起价原文保留。

默认全店监控，每 300 秒一轮；最多两个请求并发，完成每页后错开 250ms，单请求限时 15 秒，全轮限时 60 秒。Worker 在抓取期间仍持续更新心跳。GreenCloud 每个分类首轮成功建立库存基线，不发送一批初始卡片；之后补货、新增有货套餐及已发送卡片的库存变化沿用现有 TG 工作流。

监控可以选择全部、分类或单个套餐。指定分类的新增套餐自动纳入；数据抓取仍覆盖公开目录，保持完整分类浏览。分类超过六个时改用下拉框；可以按地区和配置搜索，每页显示二十个套餐，勾选跨分类及分页保持。首页的明确库存统计与数量未公开的可订购统计分开。

当前实测快照是十九个分类、四百零一个套餐，包含空类、代理和附加服务；未来以页面实际返回为准。未公开的 CPU、地区、IPv4 等字段不补猜测值。
